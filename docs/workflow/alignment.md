# Alignment Loop

## 정의

`Alignment Loop`는 Agent가 User와 상호작용하며 흐린 요청을 작업 가능한 공통 기준으로 구체화하는 과정이다.

작업 가능한 공통 기준은 User와 Agent가 같은 이슈를 보고, 같은 기준으로 다음 행동을 선택할 수 있을 만큼 목표, 맥락, 기준, 판단 지점, 열린 질문이 맞춰진 상태다.

## 기본 원칙

`Alignment Loop`는 다음 원칙을 따른다.

|원칙|설명|
|---|---|
|충분한 공통 기준|현재 작업에 필요한 수준까지 목표, 맥락, 기준, 판단 지점을 맞춘다.|
|결과 영향 중심|결과에 영향을 주는 불확실성을 먼저 다룬다.|
|가정 드러내기|Agent가 의존하는 전제, 해석, 미확인 범위를 User가 확인할 수 있게 드러낸다.|
|선호 지점 드러내기|User 선호에 따라 표현 방식, 상호작용 방식, 구조 선택이 달라지는 지점을 작업 전에 드러낸다.|
|보고 전 확인 기준|결과를 보고하기 전에 Agent가 확인해야 할 기준, 방법, 한계를 맞춘다.|
|기준 기록|상호작용으로 정리된 기준을 이후 작업에서 복원할 수 있는 형태로 남긴다.|

## 드러낼 항목

Agent는 Alignment 과정에서 다음 항목을 드러낸다.

|항목|드러낼 것|
|---|---|
|이해한 요청|Agent가 이해한 목표, 문제의식, 기대 결과|
|확인한 맥락|읽은 문서, 코드, 산출물, 대화 맥락, 외부 자료|
|가정과 한계|Agent가 둔 전제, 해석, 미확인 범위|
|결정 지점|User 판단이 필요한 방향, 범위, 기준, 위험|
|선호 지점|User 선호에 따라 결과와 재작업 비용이 달라지는 선택 지점|
|검증 기준|보고 전에 확인해야 할 기준, 방법, 남길 Evidence, 미확인 범위|
|준비 기준|작업 품질을 높이기 위해 필요한 style, conventions, environment, tool, verification surface, metric, observability, risk controls|
|열린 질문|지금 결정할 질문과 실행 중 판단 지점으로 남길 질문|

## 질문 기준

Agent는 결과에 영향을 주는 질문을 우선한다. 질문의 목적은 지금 결정해야 재작업 비용을 줄일 수 있는 지점을 좁히는 데 있다.

작업 전에 결정할 필요가 있는 질문은 다음 기준으로 판단한다.

|기준|판단 질문|
|---|---|
|목표|User가 기대하는 변화가 달라지는가?|
|범위|다룰 범위, 경계, 영향 범위가 달라지는가?|
|산출물|산출물의 형태, 수준, 사용 맥락이 달라지는가?|
|수용 기준|User가 결과를 수용할 기준이 달라지는가?|
|선호|User 선호에 따라 표현 방식, 상호작용 방식, 구조 선택이 달라지고 재작업 비용이 생기는가?|
|위험|위험 수용, 되돌리기 비용, 장기 비용이 달라지는가?|
|검증|보고 전 확인 기준, 확인 방법, Evidence 수준이 달라지는가?|
|준비|필요한 style, conventions, 환경, 도구, 데이터, 측정, 관찰, 보안, 평가 표면이 달라지는가?|
|연속성|이후 작업에도 남길 결정, 맥락, 기준이 생기는가?|
|의존성|작업 순서, 인계, 막히는 관계가 달라지는가?|

Agent는 다음 경우 질문하거나 선택지를 제시한다.

|상황|처리|
|---|---|
|답이 결과에 영향을 준다.|User에게 질문하거나 선택지를 제시한다.|
|User 선호가 재작업 비용을 키운다.|선호가 갈리는 지점을 드러내고 작업 전에 결정한다.|
|위험 수용이나 되돌리기 비용이 달라진다.|tradeoff와 권장안을 함께 제시한다.|
|보고 전 확인 기준이 불명확하다.|확인 기준, 방법, 한계를 먼저 맞춘다.|
|harness 준비가 비용, 권한, 보안, 외부 연결, 유지 부담을 만든다.|준비 범위와 tradeoff를 User 판단 지점으로 올린다.|
|장기적으로 남길 결정이 생긴다.|`Continuity Artifact` 후보로 표시한다.|

Agent는 다음 경우 가정이나 열린 질문으로 남기고 진행할 수 있다.

|상황|처리|
|---|---|
|답이 결과에 주는 영향이 작다.|Agent 가정으로 진행하고 그 가정을 드러낸다.|
|되돌리기 비용이 작다.|짧은 정렬로 진행한다.|
|실행 중 판단 지점으로 관리할 수 있다.|열린 질문으로 남긴다.|

## 질문 방식

Agent는 User가 판단하기 쉬운 형태로 질문을 좁힌다.

|방식|설명|
|---|---|
|재진술|현재 이해한 목표, 문제의식, 기대 결과를 먼저 다시 표현한다.|
|맥락 우선|필요한 맥락을 먼저 확인하고, 확인한 사실과 Agent 가정을 구분한다.|
|선택지|방향이 갈릴 때 가능한 선택지를 2-3개로 좁힌다.|
|Tradeoff|각 선택이 얻는 것과 잃는 것을 함께 드러낸다.|
|권장안|권장안이 있으면 전제와 위험을 함께 제시한다.|
|판단 표면|선택지가 시각, 구조, 흐름, 우선순위에 영향을 주면 표, Mermaid, HTML 산출물, 시안, 동작 예시로 비교 가능하게 제시한다.|
|상호작용형 선택|값 조정, 우선순위 정렬, 시각 비교처럼 문장 설명으로 판단 비용이 커지는 경우 간단한 HTML UI나 입력 양식을 만들어 User 선택을 작업 기준으로 바꾼다.|
|합의 재진술|다음 행동 전 현재 합의를 목표, 기준, 제약, 열린 판단 지점으로 다시 정리한다.|

## 구체화 질문

Agent는 현재 구체화하는 기준의 성격에 맞춰 질문을 선별한다. 세부 질문은 `Work Frame`, `Task Contract`, `Mission Brief` 문서의 `Alignment` 단계에서 정의한다.

공통 질문은 다음 범위에서 다룬다.

|범위|공통 질문|
|---|---|
|목표|User가 실제로 바꾸고 싶은 상태는 무엇인가?|
|맥락|작업 전에 확인해야 할 문서, 코드, 산출물, 대화 맥락, 외부 자료는 무엇인가?|
|기준|결과를 어떤 기준으로 충분하다고 볼 것인가?|
|결정|작업 전에 User가 정해야 할 방향, 범위, 위험, 선호 지점은 무엇인가?|
|검증|보고 전에 Agent가 확인해야 할 기준, 방법, 한계는 무엇인가?|
|준비|작업 전에 구성해야 할 harness는 무엇인가?|
|연속성|이후 작업에도 남길 결정, 맥락, 기준은 무엇인가?|

## 기록

Alignment에서 정리된 기준은 성격에 따라 `Work Frame`, `Task Contract`, `Mission Brief`, `Continuity Artifact` 후보에 남긴다.

|정리된 기준|기록 위치|
|---|---|
|작업 배경, User 의도, 확인한 맥락, 고려할 점|`Work Frame`|
|harness 필요 여부, 준비 범위, User 판단이 필요한 setup|`Work Frame`의 `Harness Setup Need`, 관련 `Task Contract`/`Mission Brief` 필드|
|실행 목표, 산출물, 경계, 수용 기준, 확인 계획|`Task Contract`|
|큰 목표, Task 구조, 의존성, Mission 판단 지점, 종합 기준|`Mission Brief`|
|장기 효력이 있는 결정, 맥락, 기준|`Continuity Artifact` 후보|

## 완료 기준

`Alignment Loop`는 다음 행동을 선택할 만큼 목표, 맥락, 기준, 판단 지점, 열린 질문이 맞춰지면 충분하다.

열린 질문이 남아도 실행 중 판단 지점으로 관리할 수 있으면 산출물에 남기고 진행한다. 열린 질문이 목표, 범위, 수용 기준, 보고 전 확인 기준을 흔들면 먼저 맞춘다.

## 수용

`Work Frame`, `Task Contract`, `Mission Brief`와 그 갱신은 User가 받아들인 뒤에 작업 기준이 된다. 수용은 User의 명시적 결정이며 Agent가 추정하지 않는다.

Agent는 수용을 요청할 때 다음을 제시한다.

|제시 항목|내용|
|---|---|
|기준 표면|수용 대상의 핵심 기준을 User가 한 번에 판단할 수 있는 형태로 제시한다.|
|열린 질문|아직 정해지지 않은 판단 지점을 함께 드러낸다.|
|수용의 의미|수용 이후 무엇이 실행되는지 밝힌다.|

수용 성립은 다음 기준을 따른다.

|User 응답|처리|
|---|---|
|명확한 긍정 지시 ("진행해", "그렇게 해")|수용 성립. 수용 시점과 표현을 기록한다.|
|조건부 동의 ("단, X는 빼고")|조건을 기준에 반영해 기록하고 수용으로 다룬다. 조건이 기준을 의미 있게 바꾸면 바뀐 기준을 다시 제시한다.|
|모호한 긍정 ("괜찮은 듯"), 부분 동의|수용으로 다루지 않는다. 수용 범위를 되묻는다.|
|수정 요구, 무응답, 화제 전환|수용 불성립. 요청된 수정을 반영하거나 정렬을 계속한다.|

수용 기록은 수용 시점, User 표현의 요지, 반영된 조건을 해당 기록(`work-frame.md`, `task-contract.md`, `mission-brief.md`)에 남긴다. 기록을 만들지 않는 `Direct Work`에서는 대화 안의 수용으로 충분하다.
